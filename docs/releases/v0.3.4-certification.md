## Complete the two-release rollback anchor

After v0.3.4 is healthy `current`, require that `previous` resolves to the exact immutable `v0.3.3` tag, its recorded SHA, and its attested artifact. Then run the v0.3.3 artifact-carried proof on the VPS from a root-controlled shell. It uses only private synthetic state and dynamic loopback ports; it does not read the production environment or state, restart production, or restore a database.

```sh
set -eu
V033_SHA='<exact-v0.3.3-40-character-sha>'
V033_ARTIFACT_SHA256='<exact-v0.3.3-runtime-archive-sha256>'
printf '%s\n' "$V033_SHA" | /usr/bin/grep -Eq '^[a-f0-9]{40}$'
printf '%s\n' "$V033_ARTIFACT_SHA256" | /usr/bin/grep -Eq '^[a-f0-9]{64}$'
resolved_previous=$(/usr/bin/readlink -f /srv/skyjo-online/previous)
test "$resolved_previous" = "/srv/skyjo-online/releases/$V033_SHA"
test -f "$resolved_previous/.skyjo-deployment.json"
test ! -L "$resolved_previous/.skyjo-deployment.json"
test "$(/usr/bin/stat -c '%U:%G' "$resolved_previous/.skyjo-deployment.json")" = 'root:root'
test "$(/usr/bin/stat -c '%a' "$resolved_previous/.skyjo-deployment.json")" = '644'
/usr/bin/printf '{"releaseSha":"%s","artifactSha256":"%s","tag":"v0.3.3"}\n' \
  "$V033_SHA" "$V033_ARTIFACT_SHA256" | \
  /usr/bin/cmp -s - "$resolved_previous/.skyjo-deployment.json"
umask 077
/usr/bin/sudo -u skyjo-canary /usr/bin/env -i TMPDIR=/var/tmp \
  /opt/skyjo-online/node/bin/node \
  "$resolved_previous/server-apns-rollback-proof.mjs" \
  --expected-release-sha "$V033_SHA"
```

The metadata comparison depends on the controller's `releaseSha`, `artifactSha256`, `tag` key order and single final LF. Retain only the validated SHAs/digest, metadata result, and the proof's bounded success line. Once that exact verified-`previous` proof passes, close #203 and unblock #204. v0.3.3 is then the permanent minimum code-rollback floor.
