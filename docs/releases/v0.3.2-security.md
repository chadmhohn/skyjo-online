# v0.3.2 security addendum

`v0.3.2` adds no application runtime code, production dependency, database, protocol, authentication, invite, cache, service-worker, or deployment-controller change. The reviewed dependency disposition and 2026-08-21 React Router exception expiry in [v0.3.0-security.md](v0.3.0-security.md) remain release-blocking, together with exact-SHA CodeQL and zero high/critical findings.

The release-test policy fails closed. Safe `GET`, `HEAD`, and `OPTIONS` requests remain allowed. The sole non-safe exception is a `POST` whose literal URL is the validated production origin plus exactly `/cdn-cgi/rum`, `/cdn-cgi/rum/`, `/cdn-cgi/rum?`, or `/cdn-cgi/rum/?`. Cloudflare documents both path variants and the production edge proved that its browser beacon may append a syntactically empty `?`; because the delimiter contains no query data, this four-form Cartesian exact set is intentional. URL parsing represents the empty-query value as empty even though the delimiter remains material in the serialized URL. Every non-empty query, bare or non-empty fragment, URL credential, noncanonical spelling, application path, lookalike, nested path, malformed URL, off-origin mutation, and other method remains a release failure. Browser resource type is deliberately not an authorization boundary because Cloudflare may expose the managed beacon as `xhr`, `fetch`, `ping`, or another browser classification.

Failure output contains only bounded reason codes, never URLs, request bodies, credentials, cookies, account data, or guest state. The exception does not relax the credentialless cookie assertion, strict public cache allowlist, offline launch, or exact solo-session restoration checks. Fresh full automation is required at the new protected-main and immutable tag SHAs. Prior persona and physical iOS product evidence may be reused only after the normalized application build and production dependency graph pass independent byte-equivalence review.
