# Skyjo APNs backend v0.3.5 release certification

> Preparation status: this document and matching version metadata prepare a candidate only. They are not evidence that `v0.3.5` exists, that production has moved, or that issue #204 is complete.

`CERT_SHA` is the exact protected-main commit selected after the APNs registry/provider source PR and this release-preparation patch merge.

## Required rollback-floor precondition

Do not merge or promote the APNs feature until v0.3.4 is healthy production `current`, production `previous` resolves to the exact immutable v0.3.3 envelope release, and the v0.3.3 artifact-carried rollback proof has passed against that installed tree. Record that bounded proof on #203, close #203, and confirm #204 is unblocked before allowing a table-creating candidate onto protected `main`.

Once `apns_devices` exists, v0.3.3 is the permanent minimum code-rollback target. The ordinary v0.3.5 promotion should leave exact v0.3.4 as `previous`; never select a pre-v0.3.3 release or restore live data to facilitate code rollback.

## Candidate scope since v0.3.4

- Creates the already-frozen optional `apns_devices` table transactionally and idempotently while keeping the public migration ledger and readiness schema at version 2.
- Adds authenticated config/register/delete contracts, optional atomic logout cleanup, capped multi-device registration, 180-day retention, rotation and account reassignment, and stable additive API errors and contract-bundle-v1 fixtures.
- Stores only AES-256-GCM ciphertext, nonce, tag, and a separately derived keyed HMAC fingerprint. Device tokens, provider JWTs, key material, account identifiers, and private provider bodies stay out of logs and retained evidence.
- Adds fixed-host Apple sandbox/production HTTP/2 delivery with ES256 token caching, bounded concurrency, queue, body, timeout, shutdown, retry, and exact permanent-token cleanup rules.
- Fans the existing authoritative post-commit turn/round/game event independently to Web Push and APNs while preserving visible-client suppression and recovered-command deduplication. APNs alerts contain generic copy and only the approved room-routing fields.
- Packages `server-apns.mjs`, preserves the exact rollback helper, verifies copied-state backup/restore, and keeps all production APNs keys outside the artifact. Canary blanks every APNs setting, cannot read the production key directory, and cannot contact Apple.
- Keeps production dependencies, public schema 2, room persistence 2, multiplayer protocol 2, contract bundle 1, and solo-AI strategy 1 unchanged. The native app still has no APNs capability or registration client; that separately reviewed consumer remains issue #189.

## Post-promotion release closure

After production is healthy at `CERT_SHA`, start from a clean checkout of the immutable tag and download the exact successful tag-run inputs:

```sh
gh run download "$TAG_RUN_ID" \
  --repo chadmhohn/skyjo-online \
  --name "skyjo-build-$CERT_SHA" \
  --dir .
gh run download "$TAG_RUN_ID" \
  --repo chadmhohn/skyjo-online \
  --name "certification-$CERT_SHA-$TAG_RUN_ID-$TAG_RUN_ATTEMPT" \
  --dir test-results
npm run certify:verify -- \
  --release-sha "$CERT_SHA" \
  --tag v0.3.5 \
  --production-base-url https://skyjo.groundworkrevops.com
```

Only after that verifier passes may an operator publish the GitHub Release from the existing tag. Attach the exact tag-run `automated.json`, `eight-client-personas.json`, `recovery-trials.json`, `rss-stages.json`, and `benchmark.json` with every SHA-256 sidecar, plus the runtime archive, checksum, and CycloneDX SBOM. Read the published release back through GitHub, require non-draft/non-prerelease state and the exact asset set, download to a fresh directory, recheck every checksum, and verify provenance against `CERT_SHA` and `refs/tags/v0.3.5`.

Real permission handling, locked/background iPhone delivery, tap routing, rotation/reinstall, foreground suppression, and multi-device delivery remain physical-device gates in #189. Do not distribute that dependent native build until this server release and the sanitized production provider proof are complete.

## Rollback
