# v0.3.7 security addendum

v0.3.7 publishes Flipvale's privacy and support disclosures without adding a new collection, authentication, storage, or notification boundary. Production dependencies remain unchanged; public schema 2, room persistence 2, multiplayer protocol 2, contract bundle 1, solo-AI strategy 1, and the APNs storage/provider contract remain stable.

- The public policy mirrors the repository-owned privacy inventory: linked account, gameplay, chat, notification, product-interaction, and deletion-safety data are used only for app functionality; the release adds no advertising, analytics, or tracking.
- `/privacy` and `/support` are static SPA routes that accept no credentials or mutations. Publishing them does not relax authorization on account, stats, admin, multiplayer, invite-membership, Web Push, or APNs operations.
- The privacy disclosure distinguishes browser Web Push from native APNs registration, states their actual cleanup behavior, and records the existing stale-room, APNs refresh, anonymized-result, backup, and deletion-ledger retention boundaries without changing them.
- Support copy asks only for platform, version/build, and an optional five-character room code, and warns users not to send passwords, cookies, invitation links, notification tokens, or hidden card state.
- Policy code is route-split from the initial game bundle and remains covered by the existing CSP, credentialless cache allowlist, and immutable runtime artifact checks.
- The post-promotion cache audit allows the exact original `card-flip.wav` path plus the existing pickup/place MP3 paths; it does not broaden accepted directories, filenames, queries, or response state.
- APNs continues to use the exact descriptor already shipped by the v0.3.3 rollback envelope, AES-256-GCM ciphertext, separately keyed fingerprints, fixed sandbox or production origin, generic payloads, and account-scoped registration/deletion. Web Push and APNs are independently settled.
- Runtime artifacts remain credential-free; canary services blank all settings and cannot read production APNs key paths. Release credentials remain bound to the current authorized account and least privilege.
- The annotated tag and promotion require current-conversation approval naming `v0.3.7` and the exact SHA; general autonomy is insufficient. CodeQL does not run automatically on tag pushes, so exact protected-main CodeQL remains mandatory.
- Rollback is code-only to v0.3.6 or another release no older than the permanent v0.3.3 envelope floor. Never restore live state or remove the frozen table to make older code appear eligible.
