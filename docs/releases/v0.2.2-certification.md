# Skyjo audio polish v0.2.2 release certification

v0.2.2 is the audio-polish successor to the deployed v0.2.1 release. `CERT_SHA` means the protected-main squash commit for issue #159, never a pull-request head.

## Release scope

The candidate may contain only the reviewed audio-polish work:

- preserve the accepted card-flip asset byte-for-byte, replace the delayed pickup and place assets, and remove the ambient loop;
- derive semantic local-turn, cleared-column, round-end, and game-end cues from typed game transitions without optimistic or reconnect replay;
- retain visual and ARIA guidance when sound is disabled, migrate stored sound settings, preserve iOS resume behavior, and permit generated fallback tones only through the CSP `media-src` directive;
- content-revision the public cue assets for offline PWA use without caching rooms, APIs, cookies, invites, or user data;
- add audio asset, controller, browser, and offline-cache gates; and
- advance package, certification identity, tests, changelog, and release documentation to 0.2.2.

Schema version 2, multiplayer protocol version 2, database migrations, room persistence, and deployment-controller behavior remain unchanged. Any change outside this scope requires the owning release gate to be repeated.

The dependency disposition in [v0.2.2-security.md](v0.2.2-security.md) is release-blocking. `npm audit --audit-level=high` must report zero high and critical findings.

## Protected-main evidence

Require every standard PR check, exact-head CodeQL, and independent non-author QA. After squash merge, freeze `CERT_SHA` and require the complete protected-main CI matrix, runtime artifact, provenance attestation, and isolated VPS canary at that exact SHA.

In addition to the existing v0.2.1 gates, the exact candidate must prove:

- the preserved flip asset has the recorded SHA-256 digest;
- pickup and place start promptly, end cleanly, and remain inside the cue duration and byte budgets;
- a semantic transition plays at most once across snapshots, resync, focus, and audio-context recovery;
- the controller respects its concurrent-voice and starts-per-second caps; and
- the installed PWA can play public cues offline while sensitive routes remain excluded from Cache Storage.

The checksummed automated evidence must identify package version 0.2.2, schema/protocol 2, Node 24, pinned k6 v2.0.0, and `CERT_SHA`. Verify it with:

```sh
npm run certify:verify -- \
  --release-sha "$CERT_SHA" \
  --evidence test-results/certification/automated.json \
  --checksum test-results/certification/automated.json.sha256 \
  --recovery-evidence test-results/certification/recovery-trials.json \
  --recovery-checksum test-results/certification/recovery-trials.json.sha256 \
  --rss-evidence test-results/certification/rss-stages.json \
  --rss-checksum test-results/certification/rss-stages.json.sha256
```

## Immutable tag and production order

1. Confirm production serves healthy v0.2.1 and create a verified state backup.
2. Create annotated tag `v0.2.2` exactly at `CERT_SHA` and push it once. Never delete, recreate, or retarget it.
3. Require the tag workflow to repeat all automated, artifact, provenance, backup, migration-canary, and isolated VPS-canary gates.
4. Require CodeQL success at the immutable tag SHA.
5. Promote only the artifact proven by those gates.
6. Verify local and public readiness, release identity, authenticated HTTP/WebSocket behavior, manifest, offline shell, and cue delivery.
7. Verify deployed evidence with the command above plus:

   ```sh
   --tag v0.2.2 \
   --production-base-url https://skyjo.groundworkrevops.com
   ```

8. Publish the GitHub Release from the existing tag only after production is green, attaching the required certification evidence, checksums, runtime archive checksum, and SBOM.
9. Close issue #159 only after production identity and the published release are read back successfully.

Failure before activation leaves v0.2.1 untouched. Failure after activation uses the existing code-only atomic rollback to v0.2.1 and re-verifies it. Never automatically restore a live database after traffic may have resumed.
