# v0.3.0 independent agent persona handoff

Run all three reviews independently against detached read-only worktrees and isolated exact-SHA servers at the same protected-main `CERT_SHA`. Each reviewer first runs `npm run test:e2e:identity` and requires local `/version` plus `/readyz` to match `CERT_SHA`, schema 2, and protocol 2. Use fresh browser/state profiles and do not share reports until all are final. Authors cannot approve their own SHA.

## Persona A: returning phone player (9 scenarios)

Use phone portrait with an isolated v0.2.2-shaped save. Cover these nine scenarios: Hard migration label; exact game ID/state preservation; Home Continue metadata; New Solo Game separation; protected setup; every cancellation route; successful atomic replacement; simulated replacement-write failure; force-close and credentialless offline Continue. The raw legacy record must not be rewritten merely by loading or continuing it, no rejected replacement may remove it, and Cache Storage may contain only public allowlisted resources.

## Persona B: first-time and accessibility player (10 scenarios)

Start with no Skyjo storage. Cover these ten scenarios at 320x568/200% text plus keyboard-only desktop and reduced motion: Home choices; direct setup focus; no record before Start; bounded 1-7 stepper; five native radio choices and Medium Recommended; 44x44 targets; fresh setup Axe; replacement-review Axe/focus trap; Escape/back focus restoration; game-over same-setup versus change-setup actions. Require no horizontal page scroll and zero serious/critical Axe findings. Physical VoiceOver and rotation remain device-session steps and must not be claimed here.

## Persona C: AI power, privacy, and controller boundaries (9 scenarios)

Cover these nine scenarios: exact-SHA JSON/checksum verification; fixed-seed determinism; reducer-legal actions; hidden-information redaction; ordered Easy/Medium/Hard/Ultra calibration; Ultra timing budget; deterministic Mixed assignment; Mixed badge persistence by player ID; multiplayer and disconnected-seat takeover remaining Hard. Inspect frames, DOM, storage, and logs for no hidden card/deck/drawn-card leakage and confirm no multiplayer protocol or room-state contract changed.

## Sanitized report contract

Return exactly this shape. Do not include credentials, cookies, game/player IDs, absolute paths, card values, raw frames, or browser storage dumps.

```yaml
persona: A | B | C
sourceSha: 40 lowercase hex characters
candidateIdentity: pass | fail
result: pass | fail
scenariosPassed: integer
scenariosFailed: integer
blockingFindings:
  - severity: P0 | P1
    area: short product area
    symptom: short sanitized description
nonBlockingNotes:
  - short sanitized note
```

The report is invalid if its SHA differs, candidate identity fails, a required scenario is skipped, or a measurement is missing/non-finite. Any P0/P1 finding blocks release and invalidates all reports at the old SHA.

Persona A/B/C must report exactly 9/10/9 scenarios respectively. Store each sanitized report as canonical JSON named `persona-a.json`, `persona-b.json`, or `persona-c.json`, plus a sibling `.sha256` containing exactly `<64 lowercase hex><two spaces><filename><newline>`. The orchestrator verifies each checksum, exact `CERT_SHA`, expected scenario count, and zero failures before combining the reports; never store raw browser artifacts or private state beside them.
