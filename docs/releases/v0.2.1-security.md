# v0.2.1 security disposition

This document records the dependency decisions for the immutable v0.2.1 successor. The v0.2.0 tag remains immutable, but its tag workflow stopped before artifact creation, canary, production activation, or GitHub Release publication. Production therefore never served v0.2.0.

## Build-chain findings resolved

The lock graph uses the fixed releases available inside every existing parent range:

- `brace-expansion` 1.1.14 is replaced by 1.1.16 and 5.0.6 is replaced by 5.0.8 for [GHSA-3jxr-9vmj-r5cp](https://github.com/advisories/GHSA-3jxr-9vmj-r5cp). The already-fixed Workbox 5.0.7 node is intentionally left unchanged.
- `fast-uri` 3.1.3 is replaced by 3.1.4 for [GHSA-v2hh-gcrm-f6hx](https://github.com/advisories/GHSA-v2hh-gcrm-f6hx).
- The direct development dependency `postcss` 8.5.17 is replaced by 8.5.22 for [GHSA-r28c-9q8g-f849](https://github.com/advisories/GHSA-r28c-9q8g-f849), which prevents previous-source-map path traversal and arbitrary `.map` file disclosure. Its declared `nanoid` dependency settles from 3.3.12 to 3.3.16; no unrelated lock node changes.
- The transitive `tar` node 7.5.19 is replaced by 7.5.21 for [GHSA-r292-9mhp-454m](https://github.com/advisories/GHSA-r292-9mhp-454m), which removes uncontrolled recursion in crafted member-selection paths. This node exists only under the CycloneDX/libxmljs2/node-gyp development toolchain, including its make-fetch-happen/cacache path.

All patched nodes are development-only: `brace-expansion`, `fast-uri`, `nanoid`, and `tar` are transitive tooling dependencies, while PostCSS is a direct build dependency. No global override, application dependency change, or source/layout change is required. `npm audit --audit-level=high` remains release-blocking and reports zero high or critical findings.

## Rejected protected-main candidate

Protected-main SHA `100ff9ccace46be43a296dc25b40e9a21282022f` contained the brace-expansion and fast-uri fixes but still locked PostCSS 8.5.17. GitHub opened Dependabot alert #5 for GHSA-r28c-9q8g-f849 before v0.2.1 was tagged. The candidate was rejected and its still-running certification jobs were cancelled.

During final validation of the replacement branch, the advisory feed also disclosed GHSA-r292-9mhp-454m against the locked development-only tar 7.5.19. Because 7.5.21 is a compatible in-range correction, it is resolved in the same replacement instead of creating another moderate exception.

No v0.2.1 tag, artifact promotion, production deployment, or GitHub Release publication came from the rejected SHA. Production remained on v0.1.1. The replacement protected-main candidate must include both corrections and regenerate automated certification, provenance, canary, and CodeQL evidence at its own exact SHA.

## Moderate React Router exception

`react-router-dom` remains on 6.30.4 for this narrowly scoped successor. npm reports the following moderate advisories, whose available remediation requires a reviewed React Router 7 migration:

- [GHSA-wrjc-x8rr-h8h6](https://github.com/advisories/GHSA-wrjc-x8rr-h8h6): client-side open redirect through backslash handling in `Link` and `useNavigate`.
- [GHSA-jjmj-jmhj-qwj2](https://github.com/advisories/GHSA-jjmj-jmhj-qwj2): client-side open redirect leading to XSS in affected `react-router-dom` versions.
- [GHSA-337j-9hxr-rhxg](https://github.com/advisories/GHSA-337j-9hxr-rhxg): constructor injection during React Router SSR hydration error deserialization.

Skyjo mounts a `BrowserRouter` client with `ReactDOM.createRoot`; it does not server-render React, hydrate an SSR data-router payload, or call React Router's SSR error deserializer. The SSR hydration advisory is therefore outside the deployed execution path.

The redirect advisories remain relevant to the client-routing surface. Most `Link` destinations are fixed same-origin paths, and dynamic game/stat destinations interpolate application identifiers into fixed path prefixes. The post-auth `next` query value is user controlled and currently accepted when it begins with `/`; that local-path check does not justify treating the redirect exposure as absent. This residual risk is accepted only to avoid inserting an unreviewed major-router migration after physical UI acceptance.

Controls during the exception:

- Keep the high-severity audit gate unchanged and review any new moderate or higher finding rather than broadening this exception.
- Do not add externally controlled `Link`, `useNavigate`, redirect, or post-auth destinations on the 6.x router.
- Require the complete browser, accessibility, visual, performance, domain, data, delivery, load/recovery, artifact, provenance, canary, and CodeQL gates for v0.2.1.
- Upgrade to React Router 7.18.1 or newer on a dedicated compatibility branch, including explicit hostile `next` path tests, before the exception expires.

The exception expires at **2026-08-21 23:59 UTC**. It must not authorize a release built after that time. If the migration is not complete, release work stops until the moderate findings are removed or a new, separately reviewed disposition is recorded.
