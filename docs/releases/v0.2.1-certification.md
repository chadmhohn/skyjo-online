# Skyjo PWA Polish v0.2.1 release certification

v0.2.1 is the security-only successor to the immutable v0.2.0 tag. v0.2.0 passed the planned physical iPhone UI session, then its tag workflow failed closed on newly published npm advisories before artifact creation, canary, deployment, or GitHub Release publication. Keep that tag unchanged and deploy only v0.2.1.

`CERT_SHA` means the protected-main squash commit for issue #152, never the pull-request head or the v0.2.0 commit.

## Successor scope

The accepted product behavior and PWA layout are unchanged. The successor may contain only:

- the targeted transitive lock updates recorded in [v0.2.1-security.md](v0.2.1-security.md);
- package, certification identity, tests, changelog, and release documentation advanced to 0.2.1.

Any application source, CSS, runtime dependency, protocol, schema, migration, or deployment-controller behavior change invalidates this carry-forward and requires the affected certification or physical step to run again.

The moderate React Router exception in [v0.2.1-security.md](v0.2.1-security.md) is valid only through 2026-08-21 23:59 UTC. The unchanged `npm audit --audit-level=high` gate must report zero high and critical findings.

## Pull request and protected-main gates

Require every standard PR check plus exact-head CodeQL and independent non-author QA. After squash merge, freeze the protected-main `CERT_SHA` and require its complete CI matrix, runtime artifact, provenance attestation, isolated VPS canary, and manually dispatched CodeQL to pass at that exact SHA.

The automated evidence must identify package version 0.2.1, schema/protocol 2, Node 24, pinned k6 v2.0.0, and `CERT_SHA`. Verify the checksummed evidence locally with:

```sh
npm run certify:verify -- \
  --release-sha "$CERT_SHA" \
  --evidence test-results/certification/automated.json \
  --checksum test-results/certification/automated.json.sha256 \
  --recovery-evidence test-results/certification/recovery-trials.json \
  --recovery-checksum test-results/certification/recovery-trials.json.sha256 \
  --rss-evidence test-results/certification/rss-stages.json \
  --rss-checksum test-results/certification/rss-stages.json.sha256
```

The already accepted physical UI evidence carries forward only while the successor scope above remains true and the complete automated/browser matrix is green. No second physical session is required for dependency-only development-tool lock changes.

## Immutable tag, production, and publication order

1. Confirm production still serves v0.1.1 and remove the disposable physical-test candidate.
2. Create `v0.2.1` exactly at `CERT_SHA` and push it once. Never delete, recreate, or retarget it.
3. Require the tag workflow to repeat all automated, artifact, provenance, backup, migration-canary, and isolated VPS-canary gates.
4. Manually dispatch CodeQL for the immutable tag and require success at the exact tag SHA.
5. Allow the production job to promote only the already-proven artifact.
6. Verify local readiness, release identity, authenticated HTTP/WebSocket behavior, and public Cloudflare health, login, manifest, version, and readiness.
7. Verify deployed evidence with the same command above plus:

   ```sh
   --tag v0.2.1 \
   --production-base-url https://skyjo.groundworkrevops.com
   ```

8. Publish the GitHub Release from the existing tag only after production is green, attaching the certification evidence, checksums, runtime archive checksum, and SBOM.
9. Close the release/program issues and milestone only after production identity and the published GitHub Release are read back successfully.

Failure before activation leaves production unchanged. Failure after activation uses the existing code-only atomic rollback to `previous` and re-verifies it. Never automatically restore a live database after traffic may have resumed.
