## Candidate scope since v0.3.2

This is a runtime-bearing release and is not byte-equivalent to `v0.3.2`. Prior automated, persona, or physical-session evidence cannot certify the changed server on its own.

- Contract bundle v1 adds language-neutral schemas and deterministic fixtures for operational identity, account/access/stats/invite HTTP, game state, public room snapshots, and both directions of protocol v2. The bundle version remains independent of server release, public database schema, and multiplayer protocol versions.
- The server adds strict JSON access-session endpoints and stable, sanitized API-error codes for native account, stats, room, and invite consumers. Browser form login, the shared site gate, account authentication, and room-membership rules remain in force.
- Protocol v2 remains version 2 while its parser, snapshot checks, command validation, UTF-16 bounds, and mixed native/PWA evidence are hardened. The immutable cached-PWA v0.3.2 validator pin remains a compatibility gate; it is not changed to the candidate release.
- The repository now contains the unsigned source foundation for a universal SwiftUI iPhone/iPad app: its strict-concurrency app target, local domain/networking/persistence/design-system package graph, configuration boundary, shared scheme/test plan, and pinned macOS/Xcode CI. It contains no Apple credentials or signing material and is not evidence of a signed archive, TestFlight build, App Store submission, or device installation.
- `SkyjoDomain` ports the authoritative solo rules, deterministic fixed/Mixed AI, wire models, invariants, and hidden-information redaction to Swift. Cross-language deterministic fixtures bind it to the TypeScript producers without changing solo-AI strategy 1 or any server version axis.
- The native access/account/home/stats foundation includes the two-cookie access gate, account/profile and public-deletion boundaries, home navigation, typed stats summaries/details/player history, and account-partitioned solo coordination. Request-identity and account-generation guards prevent stale asynchronous responses or prior-account data from re-entering the current UI state; cookies and passwords are not exposed to SwiftUI state.
- The native networking package contains the actual actor-owned authenticated protocol-v2 `RoomConnection`, not a placeholder: strict bounded codecs validate redacted personalized/shared snapshots, commands converge only after matching acknowledgement and authoritative snapshot, reconnect replays canonical wire text without optimistic mutation, and uncertain reset-room commands use account-fenced durable recovery. Mixed native/PWA tests exercise a real local WebSocket peer while retaining the pinned cached-PWA v0.3.2 compatibility reader.
- The native persistence package provides account-partitioned atomic solo envelopes, autosave conflict/recovery handling, and an idempotent stats outbox with explicit permanent/retryable failure states. Its data remains local app source/test scope and does not alter server database schema 2 or room-persistence version 2.
- `/.well-known/apple-app-site-association` becomes a direct public, bounded-cache invite-only association. Production startup requires the confirmed complete Apple application identifier; the fixed synthetic identifier is restricted to tests and isolated canaries. `?open=browser` remains the explicit browser fallback.
- `POST /api/rooms/invite/redeem` accepts only a bounded signed invite token before the shared access gate, applies a separate rate limit, returns only room code and expiry, and grants only the outer access session. It does not sign the user into an account or bypass room membership.
- The schema-2 account store freezes and validates optional APNs device-storage envelope version 1. This release accepts an absent table or the exact future table and preserves representative encrypted rows through copied-state backup, concurrent startup, readiness, and validated clean shutdown; it never creates, queries for product behavior, mutates, or deletes the table. The runtime artifact adds `server-apns-rollback-proof.mjs` only as a bounded synthetic certification helper accepted by the controller's stable root-module grammar; normal `server.mjs` startup never imports it, while the repository smoke reaches it through a no-argument source wrapper bound to freshly written full release identity. Row mismatches emit only a constant error, every unique row field is included in streamed leak detection, and SIGINT, SIGTERM, or the bounded proof timeout reaps both child servers before removing synthetic state.
- The committed unsigned native target includes the source-only v0.1.0 solo launcher and game table: explicit replacement, 1-7-bot fixed/Mixed setup, account-partitioned saves and stats recovery, board-first phone/iPad layouts, accessible summaries/settings, and provenance-checked audio. Its four-role UI/accessibility gate and exact archive-resource audit are repository release gates, but the VPS artifact does not distribute a signed iOS app. Apple credentials, device tokens, signing assets, and APNs keys are outside this release.
- Native universal-link consumption, join review, room presentation, multiplayer controls, and physical-device associated-domain proof remain owned by issue #188/PR #209. None of that source is in the v0.3.3 candidate, and the presence of `RoomConnection` does not claim native multiplayer room UI or completion of #188.
- Shared Swift and TypeScript opening guidance now uses viewer-neutral `Name: reveal 2 cards.` wording, with matching deterministic fixtures. This text-only runtime behavior does not change contract bundle 1, multiplayer protocol 2, shared snapshot envelope 2, solo-AI strategy 1, database schema 2, or room-persistence version 2.
- The release audit toolchain moves to Lighthouse 13.4.1 and refreshed transitive packages, leaving zero high or critical findings. React Router moves to patch release 6.30.6; the client rejects protocol-relative, backslash-containing, control-character, and non-local account return paths before navigation. The only accepted audit findings are the exact two reviewed moderate React Router advisories, and that narrow exception expires on 2026-09-30.

Production dependencies otherwise remain unchanged; public database schema 2, room-persistence version 2, and multiplayer protocol 2 remain unchanged. Development-only contract validators and Lighthouse are part of the repository toolchain. The changed server, client routing, invite, persistence-validation, public-association, and dependency behavior means no v0.3.2 byte-equivalence claim is permitted.

## Two-release rollback-anchor acceptance

Promotion of `v0.3.3` is only release one. After it is healthy `current`, keep issue #203 open and #204 blocked. Do not create or use `apns_devices` yet.

Prepare a later healthy successor release that contains the same envelope but not #204's table creation/use. That successor needs its own coherent version metadata, exact-SHA full certification, and a second explicit approval in the current conversation naming its exact tag and SHA. After promoting it, prove all of the following before closing #203 or unblocking #204:

- `current` resolves to the healthy successor's exact attested artifact and public identity;
- `previous` resolves to the exact immutable `v0.3.3` tag, `CERT_SHA`, and attested artifact recorded after release one;
- the `v0.3.3` previous release starts against a copied schema-2 database containing the exact frozen APNs table, remains ready, and preserves every representative encrypted row byte-for-byte;
- both promotion records, backups, readiness results, public smokes, symlink resolutions, and explicit approvals are retained as sanitized issue evidence.

After the successor promotion, use the SHA and artifact digest retained from the successful `v0.3.3` tag run. The following proof must run on the VPS from a root-controlled shell; it does not read the production environment or state, stop or restart production, or connect anywhere except dynamic loopback ports. It first binds the resolved `previous` tree to the exact recorded deployment metadata, then invokes the artifact-carried proof helper as the non-login `skyjo-canary` identity with an empty environment and private synthetic temporary state. Final publication normalizes the root-owned regular metadata file to mode `0644`; the byte comparison below also requires the controller's `releaseSha`, `artifactSha256`, `tag` key order and single final LF:
