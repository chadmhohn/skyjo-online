# v0.3.3 security addendum

`v0.3.3` changes server authentication-adjacent, invite, realtime-validation, public association, and database-compatibility code. It must not reuse v0.3.2's no-runtime-change or byte-equivalence argument. Production dependencies remain unchanged; the direct AJV packages added since v0.3.2 are development-only contract validators. The exact-SHA release audit, protected-main CodeQL result, SBOM, provenance, and the expiring React Router disposition in [v0.3.0-security.md](v0.3.0-security.md) remain release-blocking. CodeQL does not run automatically on tag pushes, so release review retains the protected-main result for the exact tagged commit while tag CI reruns the other release gates; a manually dispatched tag-ref run may supplement but does not replace that requirement.

## Access and invite boundary

- JSON access-session and account APIs enforce exact methods, JSON media type, bounded object shapes, timing-safe shared-password comparison, `no-store`, and stable sanitized error codes. Logout clears both outer-access and account cookies; an outer session never implies account authentication.
- Native invite redemption is intentionally public before the shared site gate because a valid signed invite may mint only the outer session. The endpoint applies a separate trusted-client rate limit, accepts one bounded lexical token field, verifies signature, expiry, room code, and room instance, and returns only room code and expiry. Invalid input, unavailable rooms, and rate limits expose stable codes without echoing tokens, cookies, private room state, or client addresses.
- Browser long invites and one-time install codes remain separate paths. Native redemption does not consume or weaken install-code atomicity, authenticate an account, assign a seat, or waive room-membership authorization.

## Apple association and realtime boundary

- The public AASA document contains one validated full application identifier and invite-only components; it exposes no web credentials or wildcard paths. The browser-fallback query is excluded before the general invite component. Production fails closed if the identifier is missing, placeholder, malformed, or synthetic; test/canary fallback is confined to an exact isolated context.
- Protocol v2 stays at version 2. Current ingress validates exact command shapes, IDs, revisions, UTF-16 byte/code-unit bounds, authorization, and server ownership. Public snapshots stay viewer-redacted. The immutable v0.3.2 PWA parser/validator and mixed-client tests remain pinned so new output cannot silently strand the documented cached client.
- Malformed legacy UTF-16 is converted to well-formed bounded output before persistence or projection. Raw frames, chat text, identifiers, invite tokens, credentials, and hidden cards remain excluded from release evidence and logs.

## Native solo source and evidence boundary

- Guest and account solo saves remain partitioned. Durable stats submissions preserve one stable game UUID for idempotent replay, and every retry or recovery capability is bound to the current authorized account, login generation, and coordinator instance. Logout, session invalidation, or an account switch fails closed without deleting or reclassifying the stored result.
- The solo UI/accessibility evidence uses synthetic state and credential-free simulator destinations. Hidden cards, cookies, account credentials, production state, device tokens, and private wire frames remain excluded. The provenance-checked audio resources and unsigned native archive are repository artifacts only; the VPS runtime does not sign or distribute an iOS app.

## APNs rollback envelope

This release contains no APNs provider client, registration route, delivery trigger, `.p8` key, or production device token. It does not create or use `apns_devices`. It only recognizes absence or the frozen exact table, columns, constraints, foreign key, and indexes; structural drift, triggers, views, aliases, or extra objects fail readiness/backup validation closed. Copied-state tests use synthetic encrypted bytes and assert rows never reach logs.

The runtime artifact includes `server-apns-rollback-proof.mjs` only as a bounded, artifact-only certification helper under the controller's stable `server-*.mjs` grammar. Normal `server.mjs` startup never imports it. Its direct CLI requires one exact lowercase full release SHA, revalidates that value inside the reusable runner, uses only temporary synthetic state and dynamic loopback ports, requires both servers to exit cleanly after SIGTERM before checking preserved bytes, withholds raw diagnostics, and emits one bounded success line containing the validated SHA. The repository-only no-argument wrapper loads the freshly written checksummed full release identity before calling the same runner.

The two-release order is a security and recoverability boundary. `v0.3.3` must first be explicitly approved, promoted, and verified, then become exact healthy `previous` after a separately approved successor promotion before #204 can create storage. After storage exists, code older than `v0.3.3` could reject the database and is permanently ineligible for rollback. These approvals must name exact tags and SHAs in the current conversation; repository access or general autonomy is insufficient.
