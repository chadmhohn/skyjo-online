# Skyjo v0.3.2 patch release certification

`v0.3.0` and `v0.3.1` remain immutable and unpublished. Both promoted successfully before the credentialless public-PWA gate rejected a Cloudflare-managed Web Analytics beacon; the existing release controller then performed a verified code-only rollback to healthy `v0.2.2`, without restoring or losing live data. Neither predecessor tag may be moved, deleted, or published.

## Scope and reusable product evidence

`v0.3.2` changes only the release-test request policy, deterministic regressions, release identity, workflows, changelog, and release documentation. It does not change `src/`, `server.mjs`, `server-release.mjs`, `public/`, `deploy/`, production dependencies, schema version 2, or multiplayer protocol version 2. Review must explicitly confirm that boundary.

The three independent persona passes and physical `PASS V0.3 IOS` session from 2026-07-26 may be carried forward only after an exact, independently reviewed byte-equivalence proof demonstrates that the normalized application build and production dependency graph are unchanged. Release metadata and test-policy files are expected to differ. The protected-main `v0.3.2` SHA must still run the complete automated CI and CodeQL matrix, including fresh unit, browser, accessibility, visual, Lighthouse, AI calibration, load, recovery, canary, artifact, attestation, and public-PWA evidence. Automated evidence must identify release `0.3.2` and the new exact SHA; no `v0.3.0` or `v0.3.1` automated artifact may substitute for it.

## Release gates

1. Verify the credentialless policy permits safe `GET`, `HEAD`, and `OPTIONS` requests, plus only same-origin `POST` requests whose literal URL is exactly the validated production origin followed by `/cdn-cgi/rum`, `/cdn-cgi/rum/`, `/cdn-cgi/rum?`, or `/cdn-cgi/rum/?`. Browser resource type must not change that decision. Reject non-empty queries, every fragment including bare `#`, URL credentials, noncanonical spellings, application paths, lookalikes, nested paths, off-origin requests, malformed URLs, and all other methods with sanitized reason codes.
2. Preserve the credentialless cookie assertion, strict cache allowlist, offline cold-launch, disposable guest-session, and exact Continue/restore assertions.
3. Squash issue #176 to protected main, freeze that commit as `CERT_SHA`, and require every protected-main check plus CodeQL to pass at it.
4. Prove normalized application-build byte equivalence and production-dependency-graph equivalence before reusing persona or physical evidence. Run `npm run certify:verify -- --release-sha "$CERT_SHA"` with fresh checksummed `v0.3.2` AI, automated, recovery, and RSS evidence from that SHA.
5. Create immutable annotated tag `v0.3.2` exactly at `CERT_SHA`. Require tag CI, CodeQL, canary, production promotion, credentialless public-PWA smoke, and incident recovery to pass.
6. Re-run the verifier with `--tag v0.3.2 --production-base-url https://skyjo.groundworkrevops.com`, confirm public schema/protocol 2/2 and the exact SHA, and publish only the `v0.3.2` GitHub Release. Rollback remains code-only; never restore a live database automatically.
