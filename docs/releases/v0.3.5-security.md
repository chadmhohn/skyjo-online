# v0.3.5 security addendum

v0.3.5 adds the server-side native notification registry and APNs provider boundary. Production dependencies remain unchanged, and public database schema 2, room persistence 2, multiplayer protocol 2, contract bundle 1, and solo-AI strategy 1 remain stable.

- The optional table is the exact descriptor already shipped by the v0.3.3 rollback envelope. It is created transactionally without advancing the migration ledger. Backups and copied-state canaries require the exact table and preserve representative encrypted rows byte-for-byte.
- Device tokens are accepted only through an authenticated, account-scoped, bounded contract. Registrations are capped, rate limited, retained for 180 days, reassigned atomically on account change, removed with account deletion/disablement, and conditionally retired so a stale provider result cannot delete a rotated token.
- SQLite stores AES-256-GCM ciphertext, a 12-byte nonce, 16-byte tag, and a keyed HMAC fingerprint derived from a separate key. Plaintext tokens, Apple private keys, provider JWTs, account identifiers, room state, and provider bodies are excluded from logs, fixtures, diagnostics, artifacts, and evidence.
- The provider reads a P-256 key and a separate token-encryption key only from the documented root-owned files. Partial or malformed configuration fails startup without values. The runtime artifact contains neither key; canary services blank all settings, deny the production key directory, and cannot reach Apple.
- HTTP/2 connects only to Apple's fixed sandbox or production origin and bounds sessions, streams, queueing, response bytes, timeouts, retries, and shutdown. Permanent cleanup is restricted to exact documented status/reason pairs, with the Apple timestamp fencing `410 Unregistered`.
- Native payloads use generic visible copy and only `aps` plus `version`, `kind`, `route`, and `roomCode`. They contain no actor/name, account/email, cards/state/scores, chat, invite, token, provider ID, or command ID. A tap is routing input for explicit review, never automatic room admission.
- Web Push and APNs are independently settled after the same committed room event. Existing visible-client suppression and command-replay deduplication remain authoritative, so one transport cannot block the other or manufacture another notification event.
- Release and deployment credentials remain bound to the current authorized account and least-privilege workflow. CodeQL does not run automatically on tag pushes, so exact protected-main CodeQL remains mandatory.
- The annotated tag and production promotion require current-conversation approval naming `v0.3.5` and its exact SHA; general autonomy is insufficient. Rollback remains code-only to v0.3.4 or another release no older than the permanent v0.3.3 envelope floor and must never restore live state.
