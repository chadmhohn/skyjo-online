# v0.3.1 security addendum

`v0.3.1` adds no application runtime code, dependency, database, protocol, authentication, invite, cache, service-worker, or deployment-controller change. The reviewed dependency disposition and 2026-08-21 React Router exception expiry in [v0.3.0-security.md](v0.3.0-security.md) remain release-blocking, together with exact-SHA CodeQL and zero high/critical findings.

The new policy exists only in release tests and fails closed. Safe `GET`, `HEAD`, and `OPTIONS` requests remain allowed. The sole non-safe exception is `POST` to the exact production origin and exact path `/cdn-cgi/rum` or `/cdn-cgi/rum/`, without query, fragment, or URL credentials. Browser resource type is deliberately not an authorization boundary because Cloudflare may emit the same managed beacon through `xhr`, `fetch`, `ping`, or an equivalent browser classification. All application paths, method variants, lookalikes, malformed URLs, and off-origin mutations remain release failures. Failure output contains only bounded reason codes, never URLs, request bodies, credentials, cookies, account data, or guest state.

The exception does not relax the credentialless cookie assertion, strict public cache allowlist, offline launch, or exact solo-session restoration checks. Fresh full automation at the new protected-main and immutable tag SHAs is required even though the independently reviewed persona and physical iOS product evidence may be reused under the documented runtime-equivalence proof.
