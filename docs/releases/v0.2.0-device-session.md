# v0.2.0 physical iPhone PWA session

This is the only planned user touchpoint. Start only after every automated gate and all three independent agent personas are green for one frozen `CERT_SHA`.

## Session identity

Open the disposable HTTPS Quick Tunnel candidate backed only by `127.0.0.1:4182`, not production. Before testing, confirm its `/version` shows the supplied `CERT_SHA` and protocol 2, and `/readyz` shows ready, the same SHA, schema 2, protocol 2, and three `ok` checks. The candidate must use fresh state/secrets, disposable accounts and one disposable coherent VAPID key pair, and no production environment/state copy. Its VAPID subject must still be a real public-DNS HTTPS or mailto contact URI controlled by the operator, never a special-use host, localhost, or any IP literal. Confirm startup accepted that identity before the iPhone subscribes. Its process cannot access production paths or `/etc/cloudflared`; cloudflared runs with `env -i`, isolated `HOME`, and an explicit zero-byte config. External HTTPS and WSS smoke must already be green. Do not include account details, invite tokens/codes, room codes, screenshots of private cards, notification endpoints, keys, JWTs, or payloads in the report.

Record only `PASS` or `FAIL` plus the failed step ID and a short symptom:

- [ ] **I0 Release identity:** candidate identity matches `CERT_SHA`; portrait and landscape render without a browser error.
- [ ] **I1 Invite/install:** open a fresh long invite in Safari, verify the install/browser choice, add Skyjo to Home Screen, launch it, redeem the fresh install code, and land in the intended room. Reopening the group invite creates a different one-time code.
- [ ] **I2 Background/lock/network:** in an active room, background the PWA, lock for at least 20 seconds, unlock, disable network, then restore it. Connection state appears promptly, commands stay disabled offline, and the same seat resynchronizes without a reload.
- [ ] **I3 Solo restore/offline:** start solo, reveal at least one card, force-close, relaunch, continue the same board, then cold-launch the installed PWA with network disabled. The solo shell and saved session work; multiplayer remains read-only.
- [ ] **I4 VoiceOver:** enable VoiceOver and complete two opening reveals plus one full turn. Board/grid position, face-up/down state, action guidance, pile buttons, and turn changes are understandable; focus does not enter inert cards or escape an open modal.
- [ ] **I5 200% text:** set the largest accessibility text size, test the home, lobby, active table, settings, and resume dialog at 320px-equivalent portrait. Content stays reachable, targets remain usable, and there is no horizontal page scroll.
- [ ] **I6 Reduced motion:** enable Reduce Motion, start an eight-player opening, and confirm the automated opening cadence settles within one second without flashing or essential information loss.
- [ ] **I7 Rotation/safe areas:** rotate an active game both ways. Header, opponent rail, centered deck/discard/action band, local board, modal controls, and bottom content remain clear of the notch, Dynamic Island, and home indicator.
- [ ] **I8 Audio/push resume:** enable audio and notifications using the disposable account, background and resume, then trigger a legal cue/notification. No duplicate cue plays, the audio control remains responsive, and notification handoff returns to the correct room. If delivery fails, retain the subscription for 400/403/transient provider responses, remove it only for 404/410, and record only the sanitized status, allowlisted provider reason, and endpoint origin. Remove the disposable subscription afterward.
- [ ] **I9 Two-player round:** play one complete two-player round through scoring and ready/next-round handling. Verify hidden cards remain hidden to the opponent, turn guidance is unambiguous, and the centered table mirrors a physical board.
- [ ] **I10 Eight-player stress:** join eight distinct seats, start, and finish all 16 opening reveals. Opponents scroll, the 90-110px phone center band and full-width local board never overlap, and the opening settles within three seconds (within one second with Reduce Motion).

## Defect loop

If a step fails, report only its ID and symptom. The orchestrator reopens the relevant issue, fixes it autonomously, merges a new protected-main SHA, and reruns the complete automated and three-agent certification. The replacement candidate must show the new SHA. Repeat only the failed physical step plus I0; a failure affecting shared identity, install, state, layout, accessibility, or reconnect semantics may explicitly require one adjacent physical step.

After all steps pass, the orchestrator removes the disposable candidate/state and proceeds with the immutable tag. The session does not authorize a production database restore or a tag/release publication before production is green.
