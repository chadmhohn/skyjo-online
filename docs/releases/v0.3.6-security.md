# v0.3.6 security addendum

v0.3.6 removes the shared outer password while preserving account authorization at every identity-bearing boundary. Production dependencies remain unchanged; public schema 2, room persistence 2, multiplayer protocol 2, contract bundle 1, solo-AI strategy 1, and the APNs storage/provider contract remain stable.

- Guest access grants no account identity, stats, profile, push registration, admin action, multiplayer seat, room membership, or automatic invite admission. Existing account-session checks remain authoritative for those operations.
- Signup and login require JSON, reject cross-site simple media types, apply separate bounded per-client limits, and expose only stable errors. The trusted client address accepts a syntactically valid Cloudflare header only behind the documented loopback tunnel path; direct deployments can disable that trust.
- Compatibility access endpoints never accept or compare the retired shared password, never log request bodies, and return only the fixed open-access state. Rollback may retain the old environment value without making it active.
- Invites and five-character room codes remain reusable routing inputs, not credentials. They grant neither account identity nor room membership and retain bounded parsing and verification.
- APNs continues to use the exact descriptor already shipped by the v0.3.3 rollback envelope, AES-256-GCM ciphertext, separately keyed fingerprints, fixed sandbox or production origin, generic payloads, and account-scoped registration/deletion. Web Push and APNs are independently settled.
- Runtime artifacts remain credential-free; canary services blank all settings and cannot read production APNs key paths. Release credentials remain bound to the current authorized account and least privilege.
- The annotated tag and promotion require current-conversation approval naming `v0.3.6` and the exact SHA; general autonomy is insufficient. CodeQL does not run automatically on tag pushes, so exact protected-main CodeQL remains mandatory.
- Rollback is code-only to v0.3.5 or another release no older than the permanent v0.3.3 envelope floor. Never restore live state or remove the frozen table to make older code appear eligible.
